## 改动一：云储存安全加固（C3，审计驱动）

**背景**：此前审计（`docs/云储存交互逻辑审计报告-20260926.md`）识别出 9 项数据丢失/误操作风险（L1–L9）。本轮落地其中 5 项修复（方案 A–E），修复合集聚焦三类真实攻击面。

| 方案 | 解决的问题 | 核心做法 |
|---|---|---|
| **C** 采纳前落档 | L4（采纳云端后不可撤销） | 新建 `ysp_adopt_before` 独立存储区，采纳云端前把将被覆盖的本地槽位完整内容落档（365 天自动清理）；单点落在 `applyCloudDataToStore` |
| **D** 导入防护 | L3（JSON 导入一步摧毁数据） | `handleImport` 加二次确认 + 导入前 `__full_import__` 快照 |
| **B** 盲写路径校验 | L1（陈旧回写回滚云端） | 两条盲写路径（页面切走/关闭 keepalive）改走引擎 `performSyncDecision({silent:true})`，有分歧整轮跳过不盲写 |
| **A** Tab 真实租约锁 | L2（假只读）、L5（多 tab 覆盖写） | `shouldHoldLock` 纯函数：最后交互者持锁；其余 tab 全页遮罩，仅"接管编辑"按钮可抢锁 |
| **E** 回溯引擎 + UI | L4 的配套、操作日志"只摆设" | 修 `logReplay` 的 BARRIER 判定（靠 adoptId 而非 message 正则）；操作日志模态框内新增"数据回溯"：选时间点 → 差异摘要 → 恢复；另有"恢复到最近一次导入前"入口 |

**关键正确性点（事后审查重点）**：
- C 的落档 `exportData()` 必须在 `loadData(payload)` **之前**抓取，否则抓到的是云端内容
- B 的判定基准对照**云端当前 rev** 而非本地基线
- E 的恢复走 `finalizeRestorePayload`：仅内容变更槽位 rev+1，使恢复内容以 `upload` 自动上云；纯采纳路径不误 bump

## 改动二：标记长线库存 — 按品牌筛选

**背景**：原"标记长线库存"弹窗按 **大类→批次** 两级筛选。商品数据已有 `brand` 字段，本次增加品牌维度。

**交互**（大类必选，品牌/批次均为可选并列维度，交集过滤）：
- **大类**：必选
- **品牌（可选）**：选"全部品牌"或指定品牌；仅列大类下实际存在的品牌
- **批次（可选）**：选"全部批次"或指定批次；选项来源大类下全部（未选品牌时）或该品牌下（选了品牌时）
- **交集过滤**：只选品牌 → 大类+品牌；只选批次 → 大类+批次；两者都选 → 交集；都不选 → 大类全部

**联动细节**：大类变清空品牌/批次/勾选；品牌变时若已选批次不在该品牌下则清批次+勾选；批次变保留已标记项预选。弹窗内 SID 区上方显示当前过滤范围提示。

**日志**：`inventory_long_term` 的 detail 增加 `brand` 字段（日志类型/契约不变，向后兼容）。

**提交**：
```

f837ec9 feat: 标记长线库存支持按品牌筛选（大类→品牌→批次三级联动）
```

**验证**：163 测试全绿；`npm run build` 通过。
