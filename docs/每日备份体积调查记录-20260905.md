## 五、operationLogs 的 115KB“垃圾日志”溯源（死循环）

- 日志写入点：`src/data/store.js:1076 addOperationLog`；**500 条上限**截断（`store.js:1116-1118`）；存于 `localStorage('ysp_ui')`。
- 现象：09-03、09-04 自动备份中的 500 条日志**全部**为 `cloud_sync` 类型、消息“内容一致，已对齐时间戳”，间隔约 **2.5 秒一条**，为同步死循环（`scheduleCloudSync` 反复触发 + 每次对齐都写日志）刷屏所致，真实业务日志被挤出 500 上限。
- 两轮刷屏时间戳（UTC 转北京 = UTC+8）：
  - 09-03 备份（08:30 生成）内日志：`2026-09-02T21:2xZ` ≈ **09-03 05:2x**
  - 09-04 备份（08:02 生成）内日志：最新 `2026-09-03T13:29:33Z` ≈ **09-03 21:29**
- 修复提交（死循环 + 误报 + 关键缺陷）：`1495df3`（cloudPayload 恒空致误报）、`86e5124`、`e4375e6`、`7e6c71a`（force 哨兵/apply 回调）、`6f807f1`（登录错误详情丢失 + 同步死循环）、`9901400`（启动误报未连接）→ 版本 `3.12.4`（09-04 23:53）。
- 代码中**唯一**能清空日志的入口为用户手动“清空日志”按钮（`src/App.vue:1227`，调 `clearOperationLogs`）；云端覆盖 `loadData`/`applyCloudPayload` **不触碰** operationLogs。故 09-05 归零系 09-04 用户手动清空，与用户自述一致。
