### 3.3 今日删除/新增的策略

**已删除（游客写入漏洞）：**
- `anon_insert`（游客可插任意行）
- `anon_update`（游客可改任意行 —— 曾致 `main` 数据可被篡改）
- `anon_select`（与 `anon_read_public` 重复的游客读策略）
- `anon_car_insert` / `anon_car_update`（临时过渡用的"仅 car 行例外"，收口时已撤）

**保留（2026-09-02 复核确认，共 7 条）：**

| 策略 | 操作 | 适用 | 规则 |
|---|---|---|---|
| `anon_read_public` | SELECT | {public} | 仅 `is_public = true` 的行（游客只读公开） |
| `Auth users can read own state` | SELECT | {public} | `auth.uid() = owner_id` |
| `Auth users can update own state` | UPDATE | {public} | `auth.uid() = owner_id` |
| `Auth users can insert own state` | INSERT | {public} | `owner_id = auth.uid()` |
| `ysp_state_owner_select` | SELECT | {authenticated} | `owner_id = auth.uid()` |
| `ysp_state_owner_update` | UPDATE | {authenticated} | `owner_id = auth.uid()` |
| `ysp_state_owner_insert` | INSERT | {authenticated} | `owner_id = auth.uid()` |

> 注：{public} 范围策略游客理论上可命中，但条件恒为 `auth.uid() = owner_id`，游客 `auth.uid()` 为空、且 `main`/`car` 的 `owner_id` 均已设为登录账号，故游客命中不了任何写策略。无任何 DELETE 策略。

## 附录 A：ETF 表上锁 SQL 模板（待 ETF 接入登录后执行）

```sql
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY['app_config','capital_log','holdings','pools','stock_cache','transactions']
  LOOP
    EXECUTE format('ALTER TABLE public.%I ENABLE ROW LEVEL SECURITY;', t);
    EXECUTE format('CREATE POLICY "anon_read_all" ON public.%I FOR SELECT TO anon USING (true);', t);
    EXECUTE format('CREATE POLICY "auth_all" ON public.%I FOR ALL TO authenticated USING (true) WITH CHECK (true);', t);
  END LOOP;
END $$;
```
