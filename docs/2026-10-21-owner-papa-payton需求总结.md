## 一、一句话目标

把 car 程序合并进 ysp-app，使 ysp-app 成为**双 owner 系统**：
`owner-papa` 承接 ysp 现有全部数据，`owner-payton` 承接 car 的 239 辆在库车与资金；
  car 按使用约定停止录入，源码零改；保留原程序供查历史，页面本身不加只读锁定。

## 二、两位 Owner 的定义

| 项 | owner-papa | owner-payton |
|---|---|---|
| 商品 | ysp 现有 `items`（Hot Wheels 收藏/采购/库存/已售） | car 在库车（导入后成为 ysp `items`） |
| 资金 | 现有共享 `calc` 7 旋钮 + owner=papa 的收支/借贷 | Payton 资金模块：零钱 / 投资余额 + 贷款清单实时汇总 + 非车辆收支 + 互转 |
| 业务流 | `transfers` 转运、`rushcar` 美淘 | 无（采购入口共用） |
| 历史快照 | 现有字段 | 快照中新增 payton 区块 |
| 数据来源 | 本系统既有 | 一次性从 car 导出导入 |

## 三、合并原则

1. **不是同步，是合并**：car 数据一次性导入 ysp-app；之后按约定停止使用 car 录入，源码零改，原页面仍可操作查询。
2. **唯一录入端**：合并后所有新增、编辑都在 ysp-app 完成。
3. **不用持续契约**：不再使用 `saveCarFundBalance` / `fetchCarFundBalance` 数据同步链；首页基金改由系统内部实时计算。
4. **顶部 owner 切换器**：仅 Papa / Payton 两档（默认 Papa），状态存 localStorage；首页合并总览固定显示、不随切换变。
5. **记录级 owner 字段**：items / Papa、Payton 收支记录带 `owner`；Payton 贷款明细存于 Payton 资金模块。
6. `calc` 7 旋钮是保留的**共享结算参数**，不拆 owner；`transfers`（ysp 转运）和 `rushcar` 美淘记录仍属 Papa 业务，不加 owner。

## 五、支付宝应有余额公式（第三轮按代码与真实 JSON 复核）

计算器两栏都显示带正负号的金额，最后一步是**进项小计 + 出项小计**（等价于正数进项减正数支出）。Payton's基金按带符号原值直接加到总公式；本次期初基金为负，因此显示为负出项：

| 栏 | 项目 | 数值 |
|---|---|---|
| 进 | 挖财总负债（calc.debt） | +119,667.34 |
| 进 | 借贷余额（borrow−lend） | +6,000.00 |
| 进 | Papa 已售商品销售毛利 | +23,647.18 |
| 进 | 公共支出 | −1,205.98 |
| 进 | **小计** | **+148,108.54** |
| 出 | 库存总货值 | −128,805.23 |
| 出 | 采购中金额 | −20,487.37 |
| 出 | 未确认交易 | −388.00 |
| 出 | Payton's基金 | −3,939.42（10/15 截断期初） |
| 出 | **小计（已带负号）** | **−153,620.02** |
| **支付宝应有余额** | | **−5,511.48** |

10/19 宝马售出补录后：Payton's基金变为 −3,924.42，出项小计 −153,605.02，支付宝余额回到 **−5,496.48**（与 car 当前值一致）。

**利润口径区分**：Papa 已售销售毛利 ¥23,647.18；扣公共支出 ¥1,205.98 后，首页净实际利润卡显示 ¥22,441.20。计算器分别列毛利与公共支出，不重复扣除；Payton 售车利润只在 Payton 销售页/快照展示，不再加入 Papa 销售毛利行（其实际回款已进入 Payton's基金）。

**Payton's基金传导链（关键）**：

```
期初（10/15 截断）: 零钱 −305.96 + 投资 +366.54 − 贷款 4000 = 基金 −3,939.42
补录 10-19 卖车 ¥15 后: 零钱回到 −290.96 → 基金 −3,924.42 （与 car 旧系统对账一致）
```

合并期初取 10/15 截断值；补录宝马 507 的 10/19 售出动作后自动收敛到 car 当前基线。合并后**不再从云端拉取**，改为系统内部实时计算。

## 六、payton 资金模型（三数实时算，定稿）

```
ownerRegistry.payton = {
  pocketBalance: -305.96,        // 10/15 截断余额
  investBalance: 366.54,         // 10/15 截断余额
  monthlyAllowance: 200,         // 手动“存入本月零花”按钮
  loans: [3笔 active 贷款明细], // name/startDate/dueDate/remaining/status + 新发生的借还流水
  accountTransfers: [],         // Payton 零钱↔投资内部转账记录（与 Papa 转运 transfers 区分）
  openingAt: '2026-10-15',
}

loanRemaining = Σ(payton.loans 中 status=active 的 remaining)
Payton's基金 = pocketBalance + investBalance − loanRemaining   ← 实时算
期初基金 = −305.96 + 366.54 − 4000 = −3,939.42
```

> 期初取 10/15 **截断**：10/19 宝马售车回款不在期初；宝马按 10/15 在库状态导入后，由用户在 YSP 销售页录入 10/19 售出。

**各操作对三数的影响**：

| 操作 | 零钱 pocket | 投资 invest | 贷款 loanRemaining |
|---|---|---|---|
| 采购入库选 payton **长线**(自留) | −= 最终成本（含转运分摊） | — | — |
| 采购入库选 payton **短线**(投资) | — | −= 最终成本（含转运分摊） | — |
| 售出长线车 | += 实际到手回款 | — | — |
| 售出短线车 | — | += 实际到手回款 | — |
| 零花板块非车辆收入/支出 | += / −= | — | — |
| 新增/归还贷款 | — | 新增/归还金额联动 | 贷款清单剩余同步变化 |
| 零钱↔投资互转 | 一边减少 | 另一边增加 | — |
| 自留↔投资转换 | 转出对应车辆成本 | 转入对应车辆成本 | — |
| 入库成本修正 | 自动补扣/退差额 | 自动补扣/退差额 | — |

- **买车**：只改余额，不生成财务流水。
- **卖车**：只改余额（实际到手金额），销售模块有销售记录，不生成财务流水；编辑/回滚销售时余额按差额同步修正。
- **支付宝计算器**：出项「− Payton's基金」随以上任何操作实时变化。
- **零花记录**编辑/删除时自动反向调整零钱；删除已入库车会询问是误录（返还扣款）还是遗失/报废（不返还）。

### 7.4 车辆分类约定

- 新建历史车辆专用大类：`payton库存`（不出现在采购选项）。真实数据里有旧类目 `2025JAPAN` 17 件，因此它是第五个类目值；仅在 Payton 视图显示。
- 导入车辆 `category = 'payton库存'`，批次 `'2026年10月导入'`。
- 复用 `isLongTerm`：长线 = 自留（keep），短线 = 投资（invest）。
- `payton库存` 仅用于导入的历史车；此后不再新增该类（新采购走日淘/美淘/国内三类）。

## 八、合并后的业务流程

1. **采购入口共用**：不论哪个 owner，都从现有采购模块（日淘/美淘/国内 + 批次）采购。
2. **采购中先 Papa 暂管**：现有 351 件旧采购及合并后新采购，在入库前暂按 Papa 采购中金额计入合并计算器，并显示“Papa 暂管”；入库时逐件选择最终 owner。入库转 Payton 后，Papa 采购中金额移除该件成本，Payton 零钱/投资按同额扣款，合并余额不跳变。
3. **新车编号**：沿用现有 `JP-` / `US-` / `CN-` 规则。
4. **维度随 owner 切换**：papa → 长线/短线；payton → 投资/自留（同为 `isLongTerm`）。
5. **Payton 逐件类型**：入库时每件可选自留/投资；可混在同一采购/转运批次内。购买按最终成本（含转运分摊）扣零钱或投资。
6. **车辆属性转换**：自留↔投资时，在零钱与投资间转移该车成本，基金总额不变。
7. **销售**：YSP 卖价扣快递/平台费/扣减后，以实际到手金额增加所属账户；编辑售价/回滚时余额按差额同步修正。Payton 销售利润在销售页/快照展示，不重复加到支付宝公式。
8. **Payton资金模块（新建独立侧栏模块，仅 Payton 视图显示）**：四张余额卡；三个页签“零花收支/贷款清单/零钱↔投资互转”。
   - 非车辆收支固定影响零钱；编辑/删除自动反向/调整余额；每月手动“存入零花 ¥200”并防止同月重复。
   - 贷款三笔明细，剩余合计为贷款总额；借款/还款按 car 规则联动投资账户和贷款余额，保留逐笔借还日期/金额/备注；编辑/删除同步修正余额。
   - 保留账户互转，零钱减少、投资增加同额（或反向），基金总额不变；编辑/删除按配对记录回滚。
9. **编辑与删除**：入库成本更正按差额改对应余额；删除 Payton 车时询问误录/重复（退回扣款）或遗失/报废（不返还）。已入库车可转移 owner，并调整 Payton 余额。
10. **库存/财务**：库存支持“全部/当前 owner”；Payton 销售利润和 Papa 销售毛利分开，避免同笔回款重复进计算器。
11. **editItem 防呆**：同 sid 联动加 `x.owner === item.owner` 检查。

## 九、快照与保护

- 每日快照改为**双 owner 分列 + 汇总**；10/21 已有 Papa 快照保留原 Papa 值，在同一条快照补 Payton 数据，10/19 宝马售出录入后更新 Payton/合并字段，不新增同日第二条。

- `dataProtection` 缩水检测按 owner 分组统计，避免合并后误报。

| 车辆名称 | 子分类合并到名字；若原名已含该子分类则不重复（例如普卡F1法拉利不再加第二个“普卡”） |
| 导入重跑 | 已存在 sid 一律跳过，不覆盖 ysp 后续修改/销售 |
| 车辆 ID 显示 | 列表显示短 UUID，详情可复制完整 UUID |
| 远程页 / car 项目 | 远程页本次不改（接受旧版显示/数据）；car 源码零改，停止使用但程序本身仍可操作 |
