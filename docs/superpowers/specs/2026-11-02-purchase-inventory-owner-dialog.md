# 采购入库归属交互设计

## 目标

将采购入库时逐件弹出浏览器输入框的 Owner 和 Payton 用途录入，改为一个清晰、可批量也可逐件调整的入库确认窗口。适用于同一批商品经常分属 Papa 与 Payton 的情况。

## 交互

- 单件、批量、购买组和转运记录入口都打开同一窗口，不使用 `prompt()` 收集归属。
- 每行显示商品名称、SID、单件成本、Owner 胶囊；Papa 为蓝色，Payton 为紫色，未选中状态使用浅色底。
- 选择 Payton 后，同一行显示“投资 / 自留”胶囊；默认投资。Papa 行不显示用途选项。
- 窗口顶部提供 Papa / Payton 批量设置胶囊；批量设置覆盖当前所有行，之后可逐件修改。
- 明确显示实际入库范围。若点击单件会连带同转运批次商品，说明“整组入库”及件数；购买组/转运记录入口也显示商品范围。
- 国内商品 SID 核对内容放在同一窗口，不另弹确认框。
- 入库前汇总总件数、成本及 Payton 投资/自留扣款预览。取消不改数据；确认后沿用现有入库数据逻辑和账户联动。
- 窗口可滚动，窄屏商品行自适应换行；胶囊有清楚的选中状态和键盘焦点。

## 验收

1. 一个批次可以逐件分配 Papa / Payton，且混合归属不会互相覆盖。
2. 批量设置后可以单独修正个别商品。
3. Payton 的投资/自留选择及预览与确认后的账户扣款一致。
4. 所有入库入口均不再出现逐件 Owner / 用途输入弹窗；取消不产生数据变化。
5. 使用者能在确认前看懂此次会处理哪些商品、涉及多少件和多少钱。
