# 转运确认按购买组展示设计

## 目标

在新建转运的“转运确认”弹窗里，区分不同购买组中的同名商品。待转运商品按购买组分块，每个组显示购买组号和采购日期，组内商品按 SID 汇总。

## 当前问题

弹窗目前将筛选后的待转运商品直接按 SID 聚合。购买组编号没有参与聚合，因此相同 SID 或名称在不同购买组内可能挤在同一行；行内也没有购买组上下文，用户无法判断选中的是哪次采购。

## 设计

继续使用现有的 `getPurchaseGroupKey(item)` 作为购买组身份：优先使用 `purchaseDetails.purchaseGroupId`；旧记录没有组号时，使用现有日期、网站、付款批次组合；这些字段都缺失时按商品 ID 独立成组。分组作用域同时纳入商品批次，沿用采购列表“批次下再分购买组”的边界，避免旧记录在不同批次因相同回退字段而合并。

转运弹窗中的待转运表格改为购买组分段显示。组标题展示购买组号和采购日期；没有组号或采购日期时显示明确的缺失占位。组内按 SID 聚合商品，行保留商品名称、SID、批次、数量、在途成本和转运系数。相同 SID 在不同购买组中各自形成独立行。

分组和展示只改变弹窗视图。全选、取消、单行勾选仍以商品 ID 维护 `selectedItemIds`，组内汇总行勾选时仅切换该行所属购买组内商品的 ID；跨组相同 SID 不会连带选择。批次筛选、费用输入、分摊和提交转运的既有行为保持原样。

组顺序沿用筛选后待转运商品在现有数据中的首次出现顺序，组内沿用商品首次出现顺序，避免引入新的排序口径。

## 验收标准

1. 同名或同 SID 商品若属于不同购买组，会显示在不同组块。
2. 组标题显示购买组号和采购日期；旧记录缺少字段时有可读占位。
3. 同一购买组内相同 SID 商品继续汇总数量、成本和转运系数。
4. 选择某组内的汇总行只会选择该组该 SID 对应商品；全选、取消和提交仍准确作用于商品 ID。
5. 批次筛选和转运费用分摊的业务逻辑不变。

## 影响范围

仅涉及 `PurchaseModule.vue` 中待转运商品的分组计算和转运确认弹窗渲染；购买组身份复用 `purchaseGrouping.js`，不修改商品数据结构或历史记录。
