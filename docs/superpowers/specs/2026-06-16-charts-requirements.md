## 一、需求概述

为"数据透视"页面新增两个图表，用于监控资产占用情况和排查贷款增长原因。

---

## 二、图表详细需求

### 图表1：动态总货值趋势图

| 维度 | 规格 |
|------|------|
| **类型** | 堆叠面积图（Stacked Area Chart）或堆叠折线图 |
| **X轴** | 时间轴，支持顶部切换【按周】/【按月】 |
| **周视图** | 最近 12 周 |
| **月视图** | 最近 6 或 12 个月 |
| **Y轴** | 动态总货值（金额，单位：万元） |
| **下层（绿）** | 库存总货值 |
| **上层（蓝）** | 采购中金额（含转运费） |
| **Tooltip** | 同时显示：库存总货值、采购中金额、两者相加总货值 |

### 图表2：资金与回款速度交叉对比图

| 维度 | 规格 |
|------|------|
| **类型** | 双Y轴组合图（柱状图 + 折线图） |
| **X轴** | 时间轴，与图表1联动，支持【按周】/【按月】 |
| **左Y轴** | 金额（元/万元），对应柱状图 |
| **右Y轴** | 天数（天），对应折线图 |
| **数据系列1** | 销售回款额（左轴，柱状图） |
| **数据系列2** | 贷款余额（左轴，柱状图） |
| **数据系列3** | 平均回款天数（右轴，红色/橙色折线图） |
| **交互要求** | 回款天数走高时，可对照贷款余额是否同步增长 |

---

## 三、已确认的细节

| # | 事项 | 决策 |
|---|------|------|
| 1 | **图表库** | ECharts（npm: `echarts`） |
| 2 | **数据策略** | 混合计算：存量指标从 `snapshots` 取，流量指标从 `items` 实时聚合 |
| 3 | **页面布局** | 支付宝余额计算器 → 图表区（独立模块） → 商品查询器 |
| 4 | **贷款余额口径** | `store.calc.debt`（挖财总负债）+ `financeLoanBalance`（借贷余额） |
| 5 | **销售回款额口径** | 净回款 = `saleDetails.price - saleDetails.deduction - saleDetails.express` |
| 6 | **X轴联动** | 两个图表共享同一个【按周/按月】切换控件 |

---

## 四、数据映射关系

```
图表1 库存总货值   ← snapshot.inventory.value         ✅ 快照已有
图表1 采购中金额   ← snapshot.purchase.totalCost       ✅ 快照已有
图表2 贷款余额     ← snapshot.calc.debt                ✅ 快照已有
                   + snapshot.finance.loanBalance       ✅ 快照已有
图表2 销售回款额   ← items[status=sold] 按 saleDate    ⚠️ 实时聚合
图表2 当期销售额   ← items[status=sold] 按 saleDate    ⚠️ 实时聚合（用于回款天数）
```

## 六、技术预研

### 快照数据结构（现有）

```js
{
  date: "2026-06-16",
  calc: { debt, wechat, publicExp, unconfirmed, fund },
  finance: { loanBalance, publicExpense },
  profit: { totalActualProfit },
  inventory: { value, count },
  purchase: { totalCost, count },
  payton: { yebBalance },
}
```

### 缺失字段（需补充至快照）

- `sold.revenue` — 当日净回款额（便于后续只用快照）
- `sold.count` — 当日售出件数

> 短期用 items 聚合，后期可选扩展快照。

### ECharts 版本选择

- npm: `echarts` (~1MB gzip ~300KB)
- 可按需引入所需图表类型减少打包体积
