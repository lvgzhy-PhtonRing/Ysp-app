# 多标签与多设备并发写入保护设计

## 目标与边界

用户在同一浏览器打开多个标签、或在不同设备同时使用主程序时，任何旧数据都不得静默覆盖较新的本地或云端数据。保留现有逐槽位比较、人工冲突选择、每日 JSON 备份和 `car` 行协议；本次不改业务数据结构，也不做逐商品自动合并。

## 方案选择

仅修前端租约可减少同浏览器误操作，但跨设备仍有「预检后另一设备写入」的竞态。选用完整方案：同浏览器使用浏览器原生独占锁；云端 `main` 行新增单调递增的 `revision`，数据库原子拒绝过期写入。数据库迁移仅约束 `main` 行，旧页面缺少版本递增时拒绝其写入；`car` 行维持现状。用户于 2026-10-24 明确指令实施。

## 同浏览器

- 页面启动先取得同源独占编辑锁，成功后才开放操作。其他标签显示只读遮罩，并禁用后台同步、主数据和 UI 状态保存；不可用的浏览器安全地保持只读。
- 不再用单个共享 `ysp_tab` 心跳键决定写权限。旧标签修改 `ysp_data` 的 `storage` 事件使当前页立即失去编辑权并提示重新加载。
- 只读页不能强抢锁。关闭其他编辑页后，可点击「重新取得编辑权」，取得后重新读取本机数据；浏览器关闭页面会自动释放锁。
- 界面拦截点击和键盘输入，保存与同步入口再次校验锁，防止仅靠遮罩保护。

## 不同设备

- `ysp_state` 加 `revision bigint not null default 0`。仅 `id='main'` 的更新要求 `NEW.revision = OLD.revision + 1`，由数据库设置 `updated_at`；旧客户端原样 PATCH 将被拒绝。
- 云端读取返回 revision；创建行用初始 revision 0；更新时在同一数据库操作中要求当前 revision 等于预检值，再写 revision+1。零行更新代表数据已变化，绝不转成 INSERT。
- 同步引擎先在内存中合并，写入成功后再应用到本地。若版本冲突，保留当前本地内容，重新拉取云端并重新计算逐槽位方案；同槽冲突重新展示差异。重试有次数上限，持续争用时明确报错并保留本地数据。
- 内容相同的槽位保留两端较高 `_rev`，防止整包上传使版本倒退。关闭前 keepalive 同样携带预检 revision，失败时不冒充同步成功。

## 验收

两个同源标签只有一个可保存或上传；只读页无法点击穿透、不能借键盘操作、不能写 `ysp_data`。两设备同时基于同一 revision 上传时只有一个成功；失败方本地数据不变，重读后自动合并不同槽位、同槽重新请求选择。旧客户端写 `main` 被数据库拒绝，`car` 更新不受影响；迁移前新客户端拒绝危险写入。完整测试与构建通过，并用模拟并发验证真实浏览器交互。

## 发布顺序

先保留云端和 Downloads 备份，再执行数据库迁移并确认旧版写入被拒绝；随后发布新客户端。若无法访问数据库管理端，本次代码和迁移脚本留在本地，不把要求 revision 的客户端单独推到线上。
