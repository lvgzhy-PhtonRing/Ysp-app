## 云端数据库和 API

| 用例 | 实测结果 |
|---|---|
| 同一所有者从两个独立登录会话读取 | 返回相同的 `main` 账本，`is_public=false`。 |
| 匿名、已登录其他账号读取 main | HTTP 200，均返回 0 行。 |
| 已登录其他账号尝试修改 main | HTTP 200，返回 0 行。所有者重新读取，商品内容和修订号保持原值。 |
| 所有者请求将 main 公开 | HTTP 200，返回的 `is_public` 仍为 false。 |
| 同一修订号竞争 | 用两个独立登录会话和实际同步客户端生成相同 `revision=eq.3` 的 PATCH，拦截后先后放行。A 返回 1 行，B 返回 0 行并被客户端识别为修订号冲突。最终修订号为 4，商品保留 A 的修改。 |
| 旧客户端省略修订号 | HTTP 试验超时，重新读取确认无写入。随后在同一云数据库以所有者的 authenticated 身份执行实际 UPDATE，触发 SQLSTATE 40001，修订号仍为 4。 |
| 固化 car 档案 | 所有者新增成功（201），试改和试删均被拒绝（403）。另一个账号无法代所有者插入（403），也读不到档案（200，0 行）。匿名读取被拒绝（401）。 |

## 应用界面

桌面 A/B 使用同一台电脑上的两份隔离 Chrome 浏览器资料，分别登录。移动查询页以独立的移动尺寸 Chrome 会话打开。均连接真实 Supabase 验收项目。

| 用例 | 实测结果 |
|---|---|
| 桌面 A/B 登录与同步 | 两份资料通过实际页面登录和拉取，读取同一测试商品。 |
| 同浏览器多标签 | A2 显示“本页暂时只读”。A1 改名并上云，关闭 A1 后 A2 取得编辑权，从共享本地存储读到新值，随后自己的改名也上云。 |
| 同一商品冲突 | B 离线改名，A 改同一商品并先上云。弹窗呈现双方的实际值。B 未选择而刷新后，本地业务时间和云端修订号都维持原值。选“用云端”后采用 A 的值。 |
| B 短暂打开后关闭 | B 无本地编辑。A 上云后，B 从打开页面开始约一秒后关闭，再打开核对。A 的云端值和修订号 23 均保持不变，B 仍保有原业务时间和本地值。 |
| 用本地与都留 | 选“用本地”后两端采用 B 的值。选“都留”后实际下载的冲突副本中保存原来的云端商品，云端与两端最终保留 B 的值。 |
| 不同模块 | A 改库存商品，B 离线记公共支出 12.34 元。B 重新连接并保留 A 的商品数据。最终两件变更均可在云端读取，收支只存在一条。A 拉取后也得到该收支。 |
| 已过期的冲突选择 | B 弹窗显示第二版时，A 又提交第三版。B 选择旧弹窗的“用云端”时重新出现包含第三版的差异，旧值未落盘。重新确认后采用第三版。 |
| 写入请求失败与重试 | 拦截 B 发出的 PATCH。B 保留未同步的本地改名，云端修订号未变。解除阻断并点击“立即同步”后保存成功，A 拉取读到改名。 |
| 移动端和身份隔离 | 匿名显示登录界面。其他账号登录后提示无主账本读取权限。所有者登录后在库存看到同名商品，退出后再次打开仍显示登录界面。相关操作没有发出业务表写请求。 |
