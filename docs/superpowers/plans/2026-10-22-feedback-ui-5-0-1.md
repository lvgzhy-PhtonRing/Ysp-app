# 人工使用反馈 UI 与 5.0.1 发布实施计划

> **For agentic workers:** 执行本计划时使用 `superpowers:executing-plans`，按任务逐项完成并验证。

**Goal:** 完成已批准的 12 条人工使用反馈 UI 调整，将应用版本从 5.0.0 升至 5.0.1，验证后提交并推送 GitHub。

**Architecture:** 沿用现有 Vue 模块结构，HomeModule 负责首页 Owner 分组与跨 Owner 区块，App.vue 控制全局 Owner 开关显示，库存排序使用可测试的纯函数。仅改变显示顺序、Owner 展示范围和文案，不迁移或覆盖业务数据。

**Tech Stack:** Vue 3, Vite, Vitest, Tailwind CSS.

**Spec:** `docs/superpowers/specs/2026-10-22-manual-feedback-ui-design.md`

## Global Constraints

- 保持 Papa/Payton 余额和业务计算逻辑不变；Payton 基金说明由实时 pocket、invest、活跃贷款计算。
- 数据透视全局区块（余额计算器、商品查询器、各批次回款统计）跨 Owner；Owner 组及库存/销售视图仅使用当前 Owner。
- Payton 的 `isLongTerm` 业务字段不改，仅将指定 UI 文案改为“自留”。
- 提交时仅暂存本计划涉及的文件，不包含已有未跟踪文件。

## Review Focus

- Owner 切换后首页全局与 Owner 组范围混淆：测试两种 Owner 下查询器仍包含双方商品而指标组跟随当前 Owner。
- 库存跨 Owner 泄漏：测试筛选及统计只包含当前 Owner。
- 排序副作用：测试升序/降序独立切换名称与品牌，且不修改输入数组。
- Payton 基金计算口径漂移：测试使用活跃贷款明细与实时余额，忽略已还清贷款。
- 单 Owner 页面切换器仍出现：检查采购管理、美淘记录隐藏，其他相关页面保留。
- 版本发布混入无关文件：提交前核对 staged diff 和远端状态。
