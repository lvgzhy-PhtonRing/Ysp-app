# 上海个体工商户报税与 ysp 自动化导出系统设计

更新日期：2026-10-26

## 一、目标与结论

设计一个在 ysp 内生成 Excel 报税工作簿的功能，帮助纳税人按官方电子税务局的申报步骤整理、核对数据。工作簿用于准备和复核，不直接登录税务网站，不自动判断最终应纳税额，也不自动提交申报或缴税。申报人仍需以税务系统当期页面、预填数据和适用政策为准，核实后自行提交。

本设计依据两份《开业第一课》操作指引：小规模纳税人增值税及附加税费申报（2024-07-11）和经营所得个人所得税月（季）度预缴申报 A 表（WEB 端，2024-08-21）。两份材料展示的是当时的页面流程；税务系统界面和申报规则可能调整，导出工作簿必须提示用户核对当前页面。

## 二、官方申报步骤如何映射到导出流程

### 2.1 增值税及附加税费

操作指引展示了两种申报方式，工作簿应为两种方式提供核对资料：

1. 登录电子税务局，进入“我要办税 → 税费申报及缴纳 → 增值税及附加税费申报（小规模纳税人适用）”。
2. 若系统显示确认式申报，先检查系统归集数据；遇到未开票收入或其他经营收入时，按实际情况补充。需要填写表单时进入“我要填表”。
3. 若系统显示填表式申报，先核对系统按发票等信息预填的数值，再按实际情况调整并补充附表。
4. 预览申报表，核对无误后提交，并按页面要求确认申报声明。

ysp 工作簿提供对应期间的销售明细、汇总和待确认项目，供纳税人与税务系统预填数据逐项核对。工作簿不预设每笔销售属于免税、应税、未开票或特定货物/劳务类别，因为现有商品记录没有完整的税务分类、发票类型和开票金额。

### 2.2 经营所得个人所得税 A 表

操作指引展示的 WEB 端流程为：

1. 使用投资人手机号或证件号、密码和验证码登录，或用个人所得税 APP 扫码登录。
2. 进入“我要办税 → 经营所得（A表）”，选择申报年度。
3. 录入或确认被投资单位信息，并填写税款所属期。
4. 填写收入总额、成本费用、弥补以前年度亏损等页面要求的数据；按页面提示确认综合所得中的投资者减除费用、专项扣除和其他扣除如何处理。
5. 选择适用的减免事项，核对系统计算结果。
6. 确认申报信息并提交，在成功页面或申报记录中确认已提交。

工作簿按所选所属期提供销售收入、已售商品成本、现有费用记录和缺失数据清单，并为纳税主体、所属期、扣除选择等需要在税务页面确认的内容保留人工核对栏。工作簿的经营数据汇总不等同于税法上的应纳税所得额；未完成费用性质、纳税主体和扣除资格核对前，不自动生成应纳税所得额或应纳税额。

## 三、ysp 当前数据能力与边界

| 数据 | 当前可读取字段 | 可用于工作簿 | 缺口或限制 |
|---|---|---|---|
| 已售商品 | 商品名、SID、Owner、成本；saleDetails.date（下单日）、saleDetails.entryDate（确认到账日）、确认状态、售价、快递费、平台费率、扣减、利润、销售渠道 | 仅按已确认销售的 entryDate 列入税期，提供经营参考汇总 | 下单日只用于经营统计，不用于税务工作簿归期；未确认或缺少/无效入账日的销售列入待确认事项；没有完整发票类型、开票金额和税务商品类别 |
| 收支记录 | 类型、日期、项目、金额、备注、Owner | 导出收入/支出明细并按期间筛选 | 没有经营/个人标记及费用科目；不能把所有支出都当作可扣除费用 |
| 借贷记录 | 类型、日期、对方、金额等 | 可作为辅助核对信息单独列示 | 借款、还款不能直接当作营业收入或费用 |
| Owner 与纳税主体 | 商品及部分记录有 Papa/Payton Owner | 可用于筛选候选记录 | Owner 不等于纳税主体；系统没有营业执照主体与 Owner 的正式映射 |
| 固定资产 | 无独立模块 | 不纳入本期自动税额计算 | 资产原值、启用时间、折旧政策等需另行建账 |

因此，旧稿中“现有字段已可精确生成全部报表、人工只需照抄”的表述不成立，应改为：ysp 可整理部分经营明细；税务分类、扣除资格和纳税主体仍需人工确认。逐件成本可作为经营核对数据，但不代表税务机关已认可其税务处理。

## 四、推荐方案：一个按税期生成的 Excel 工作簿

### 4.1 工作簿结构

文件名建议为“YSP报税工作簿_纳税主体_期间_生成日期.xlsx”。工作簿包含以下工作表：

| 工作表 | 内容 |
|---|---|
| 阅读说明 | 纳税主体、所属期、生成时间、数据版本、使用范围、申报页面步骤和口径说明 |
| 申报步骤清单 | 分别列出增值税申报与 A 表申报步骤，设置“已核对/需补录/不适用”栏 |
| 增值税核对 | 按期间汇总销售金额并列出与税务系统预填金额的人工核对栏；税务类别、发票数据缺失时显示“待确认” |
| A表经营数据 | 收入、已售商品成本、现有费用的经营参考汇总；纳税主体、所属期、以前年度亏损弥补、扣除选择和系统税额由申报人核对填写。以前年度亏损弥补没有 ysp 数据来源，留空供人工填写 |
| 销售明细 | 按期间导出商品、SID、Owner、销售渠道、入账日期、售价、成本、平台手续费、快递费、补差和经营利润参考；不展示下单日期 |
| 补差明细 | 单独列出已确认销售的补差金额及方向，正数为卖方补给买家，负数为买家补给卖方 |
| 收支明细 | 按期间导出收入与支出原始记录，保留日期、项目、金额、备注和 Owner；增加空白“税务归类/是否计入本次核对”栏，默认待确认 |
| 补差明细 | 对有补差的已确认销售按入账日单独列行，说明补差金额方向 |
| 待确认事项 | 缺失日期、未映射纳税主体、费用未分类、发票信息缺失、系统预填差异等问题和对应记录编号 |

汇总金额由原始明细生成；来源记录可追溯。金额显示两位小数，汇总使用未提前逐行取整的原始数值，避免明细舍入误差。

### 4.2 用户操作流程

1. 从“数据操作”进入“报税导出”。
2. 选择纳税主体及本次纳入的 Owner。主体映射尚未设置时，要求先人工选择，不默认把 Papa、Payton 或全部记录视为同一纳税主体。
3. 分别选择增值税申报期间和经营所得 A 表期间；期间起止日期采用本地日期，起止日均包含。
4. 预览数据行数、合计金额和待确认事项。缺少日期的记录不悄悄计入某期，而是列入待确认事项；收入、支出不因缺少类别而自动作税务扣除判断。
5. 下载 Excel 工作簿。导出只读取当前数据，不修改商品、收支或 Owner 数据，不上传工作簿。
6. 用户在官方税务系统中按清单操作，将税务系统预填值与工作簿核对；需要补充的税务分类、扣除和差异说明由用户在税务系统或工作簿人工填写。
7. 用户确认并提交申报后，可自行保存已填核对版；ysp 不代替税务系统保存申报结果。

### 4.3 汇总口径与安全校验

- 销售收入按已确认交易的 saleDetails.entryDate（确认到账日）归入所选期间，起止日期均包含；工作簿不展示下单日 saleDetails.date。未确认、缺少入账日或入账日格式异常的交易不计入期间汇总，并在待确认事项中列出。
- 已售商品成本按同一批销售记录关联的 item.cost 汇总。它是经营核对口径，不能自动证明该成本可税前扣除。
- saleDetails.express、平台手续费（售价 × feeRate）和 deduction 单独列示；补差另有独立明细表。快递费随销售按入账日归期是本工作簿的整理口径，并不当然等同税法口径。参考利润为售价 − 商品成本 − 平台手续费 − 快递费 − 补差，仅作经营参考，不等同应纳税所得额或税额。只有在费用性质及凭证符合要求后，才由申报人决定是否用于税务填报。
- finance.records 的支出先按原始金额展示；因缺少费用科目和凭证状态，默认不自动并入“可扣除费用”。收入记录也不与销售收入重复累计，除非用户明确标记用途并完成去重核对。
- 增值税销售额不自动拆分免税、应税、未开票、货物劳务或不动产等申报类别；工作簿提供明细和人工分类栏，由用户根据税务系统当期规则核实。
- 借款、还款、账户余额、库存余额不并入销售收入或费用汇总，作为独立辅助信息处理。
- 若纳税主体映射缺失、期间存在无日期销售、以前年度亏损弥补需要人工核实，或需填报字段没有来源数据，导出仍可生成，但首页和“待确认事项”明确提示，不显示成已核实的零值。

## 五、系统方案比较

| 方案 | 优点 | 代价/限制 |
|---|---|---|
| Excel 工作簿（本次选择） | 可多表组织明细、汇总、流程清单和待确认事项；适合人工复核及留档 | 需要新增工作簿生成能力；数据口径需持续维护 |
| 多个 CSV | 生成逻辑简单、文件轻 | 缺少统一说明和跨表汇总，用户需自行整理 |
| 税务网页自动预填 | 操作步骤最少 | 依赖登录态和页面结构，易受页面/规则变化影响；错误提交后果较大 |

采用 Excel 工作簿方案。第一阶段只做浏览器本地生成和下载，不做税务网站 RPA，不做自动提交、自动缴税或后台上传。未来若讨论网页预填，应单独评估并保留用户最终核对和提交动作。

## 六、分阶段实施建议

### 阶段一：可核对的工作簿导出

- 增加纳税主体及 Owner 纳入范围选择、税期选择、导出预览。
- 输出上述工作簿和待确认事项；原始业务数据只读，不改变现有 JSON 格式。
- 增加缺失日期、金额字段异常、纳税主体未映射、可能重复收入等提示。
- 支持导出前预览与文件名核对，避免误选期间。

### 阶段二：补齐税务数据字段

先确认实际办税主体和征收方式，再讨论是否新增：纳税主体映射、费用科目/经营性质、发票类型及开票金额、税务分类、凭证状态和附件索引。新增字段须先明确业务含义和历史记录默认值，不能把历史未知值批量设为已确认值。

### 阶段三：规则维护与可选网页辅助

税率、减免政策、表单栏次和申报期限应来自可追溯、注明生效期间的官方规则，并由用户或税务专业人员确认。规则更新前，导出器不得静默沿用过期税率。网页自动预填不属于本次方案；若未来启用，应保持人工逐项复核、人工点击提交。

## 七、验收标准

1. 相同数据和相同纳税主体/期间选择，生成相同明细和汇总。
2. 每个汇总数字都能追溯到工作簿明细行和 ysp 原始记录。
3. 纳税主体不明确、确认到账日缺失、交易未确认、费用类别未知时，均显示待确认，不被当作已核实的零或可扣除金额；工作簿不显示销售下单日。
4. 销售收入与收支记录不会被无条件重复累计；借贷、账户余额和库存金额不混入经营收入/费用。
5. 导出只下载文件，不修改或上传 ysp 业务数据。
6. 工作簿中的操作步骤与官方税务系统当期页面不一致时，以当期系统为准，并提示更新说明。
