## 一、任务背景（用户 4 条需求）

1. 只做操作日志的改造，**不要动其他功能**
2. 完整性：每日快照 + 操作日志能完整回溯到某个时间点的数据
3. 改进"查看详情"：第一层简要（如"删除了5件库存"），详情显示 5 件商品名称等详细信息
4. 分层 UI：第一层简要清晰、第二层详情；无第二层信息不显示查看详情按钮

## 二、用户已确认的决策（AskUserQuestion 结果）

- 验证深度 = **补全日志 + 自动验证**（不做用户可见的恢复功能界面）
- 详情形态 = **行内展开**（移除日志详情弹窗）

## 三、关键研究结论（已完成，勿重复探索）

- 日志单点写入：`src/data/store.js` `addOperationLog`（~1076 行）；`{id, time, type, message, detail}`；500 条上限；存 localStorage `ysp_ui`（`ysp_data` 与云同步**不含**日志）
- 删除聚合：同 type + 同 sid 在 500ms 内合并为一条（`DELETE_LOG_TYPES = {inventory_delete, purchase_delete}`）
- 详情弹窗无用原因（App.vue 1268-1385）：重复 message、日志ID/字段数无意义、`getLogDetailEntries` 白名单 13 字段、嵌套对象显示"[复杂数据，请查看上方明细]"
- 每日快照仅 8 个汇总指标（`takeDailySnapshot` ~689 行），无商品级数据
- `clone()` 已在 store.js 导出（JSON 深拷贝）
- 测试为 co-located（`src/**/*.test.js`），`npm test` = vitest run；现有测试**不引用**日志
- **硬约束**：写时 message 不能改（`attachHistoryMetaFromOperationLog` 供 undo 栈标签复用）；第一层简要语句由 UI 层从 detail 生成、旧日志回退 message；只加 detail 字段不改业务逻辑
